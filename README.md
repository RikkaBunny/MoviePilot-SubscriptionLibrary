# 订阅媒体库 · MoviePilot Subscription Library

将 MoviePilot 的订阅列表作为持久的媒体保留清单。面向 **MoviePilot v3.0.4** 开发，使用原生插件 SDK、事件及调度服务。

## 行为

| 在订阅界面的操作 | 对应行为 |
| --- | --- |
| 新增订阅 | 由 MP 正常搜索、下载、整理；新订阅解除该媒体的旧归档保护 |
| 下载齐全 | 在宿主“完成前检查”阶段保留订阅，避免自动结束后从清单消失 |
| 暂停订阅 | 保留媒体，暂停状态仍属于保留清单 |
| 取消订阅 | 删除已关联的下载任务、源文件及媒体库文件，再清理对应历史并刷新媒体服务器 |
| 起始集从 50 改为 80 | 按文件级集数信息清理 80 之前的内容；混合包保留需要的文件并将冗余文件下载优先级设为 0 |
| 缩小手动总集数 | 清理手动上限之后的内容；自动元数据总集数变化不触发删除 |
| 容量插件清理较久未看的内容 | 订阅保留，被清掉的集数记为归档，阻止自动补下载；新集仍能追更 |
| 在插件设置选择“恢复下载”并保存 | 解除选定媒体的归档保护，下一轮订阅搜索可重新获取 |

同一媒体存在多个订阅时，采用各自保留范围的并集。以媒体来源、ID、类型、季号和剧集组识别归属，不通过标题猜测，也不把订阅 ID 当作媒体 ID。

## 安装与配置

1. 在 MoviePilot 插件市场的自定义仓库设置中加入本仓库地址：
   `https://github.com/RikkaBunny/MoviePilot-SubscriptionLibrary`。
   私有仓库需由宿主支持的仓库访问配置授权读取；没有此配置时不能直接匿名安装。公开仓库可直接读取。
2. 安装 **订阅媒体库**。首次安装默认停用，且默认开启演练。
3. 填写 MP **容器内**的下载目录和媒体库目录，每行一个。必须是明确的绝对目录，例如：

   ```text
   /media/downloads
   /media/library/tv
   /media/library/movies
   ```

   不接受 `/`、`/media`、`/config` 等宽泛目录，不接受通过父级符号链接访问的目录。所有待删除的下载器路径必须由 MP 自身的路径映射投影到这些目录。
4. 开启插件，保留“下载完成后保留订阅”和“容量清理后防止重复下载”，打开“保存后立即同步一次”，保持**演练**。
5. 在插件详情查看文件、任务、历史记录及警告预览。核对目录、身份、季号、手动集数范围后，关闭演练，启用正式同步。正式模式会永久删除对应文件。
6. 如原来有外部脚本执行同一策略，停用该定时任务，避免它绕过插件的保留规则。无需 1Panel 定时任务来运行本插件。

默认每 2 分钟巡检，订阅新增、修改、取消或整理完成时也会请求宿主提前运行。请求未成功时，持久队列由下次巡检继续处理。

### 与“磁盘清理”插件并存

本插件不实施 1 TB 配额或 60 天观看策略，这些仍由磁盘清理插件配置。容量清理的阈值是清理触发线，不能保证任意瞬间的使用量严格不超过 1 TB。

先让本插件完成一次媒体观察并确认归档保护正常，再恢复容量清理。它会记录已整理媒体的位置和集数；即使容量清理插件直接删掉 MP 历史、没有发送事件，下一次巡检或自动下载前也会检查旧文件是否消失并建立归档。

归档不删除订阅。自动订阅搜索和下载会拦截归档集数；包含归档集数的整季包，以及无法证明只含新集的资源，保守拦截。新单集不受影响。明确选择的非归档集数允许下载。用户手动下载可以越过归档保护。

## 支持范围与边界

- 首版支持 **qBittorrent + 本地文件系统**。其他下载器、云盘、音乐和光盘目录结构尚未提供删除适配器；不猜测删除方法。
- 只处理宿主历史和下载器文件清单能够证明归属的文件。定期快照比较会补上先前已观察订阅的漏发取消事件。没有 MP 关联记录的手动文件、安装前已经取消的订阅、首次观察前发生的取消，需要先核对并建立关联；不会扫描标题后直接清空整个硬盘。
- 下载完成保留通过 `SubscribeCompletionCheck` 否决完成操作，不重新创建订阅，不改宿主数据库，不修改宿主代码。保留后的订阅仍使用 MP 自己的状态和进度展示。
- 无法识别季号、集数或本地存储关系时保留文件并报告警告。受影响的取消意图持续排队，可在纠正宿主记录后重试。
- 一个媒体文件同时包含需要和不需要的集数时保留整个文件，不剪切视频。
- 硬链接只在配置目录内查找。若其他仍订阅媒体引用同一文件或 inode，保留共享内容。目录外的硬链接不会删除，也不能保证释放其占用空间。
- 配对字幕、NFO 和图片采用同一视频文件名词干识别；无法归属的海报、额外素材保留。
- 记录的是文件消失，不是容量插件专有删除事件，因此其他外部程序删除已观察到的媒体也会建立归档。先完成基线观察，才能保护后来被清掉的内容。
- 目录挂载基线改变时停止清理及归档判断。先恢复并核对挂载，再使用“重新建立目录基线”；该选项会丢弃旧的文件存在性观察，已有归档仍保留。
- 订阅更新与下载器/文件系统之间没有跨服务事务。逐步检查、暂停任务、文件校验及持久重试用于缩小竞态窗口，无法实现全系统原子删除。
- 演练只禁止清理操作；“保留已完成订阅”和归档下载拦截仍会生效。

## 状态、维护和升级

插件详情提供最近预览、取消队列、归档、未完成操作及错误。只有文件和任务删除成功后才请求移除历史；宿主返回成功后还会确认记录实际不存在。失败保留队列，下次巡检重试。

设置和状态通过 MP 的插件存储保存，不保存下载器密码或服务器 API 密钥。备份 MP 的配置及插件数据即可保留取消队列、归档和重试计划。取消并重新订阅相同媒体也能解除归档。

升级宿主前先切换为演练，检查 [宿主接口清单](docs/architecture.md)，验证完成前检查、查询、下载器和历史 API。升级本插件保持设置及数据，使用插件市场更新或选择已发布版本。停用本插件后，MP 恢复其原生完成订阅行为；若容量清理仍在运行，归档保护也随之停用。

## 开发与验证

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q plugins.v3 tests
python3 tools/build_release.py
```

测试使用 SDK 边界替身和真实临时文件，包括硬链接、叶子符号链接、文件替换、取消后重新订阅、下载器失败及跨重启重试。它们不操作服务器或真实媒体。

当前验证分开记录：78 项规则/适配器测试通过；本机与宿主容器各 10 项隔离文件/状态 QA 通过。原 SDK 下载检查使用了非规范字段，真实订阅测试发现自动下载误拦截；0.1.2 已修复，相关测试输入已纠正。**已通过原生插件市场在 v3.0.4 安装、更新，演练和定时巡检正常，正式模式成功完成空清理计划同步**。真实下载、入库、取消删除继续验收；空计划同步和测试替身不能证明生产删除链路。详情与可复现命令见 [QA 记录](docs/QA.md)。

结构和扩展方式见 [架构文档](docs/architecture.md)，发布记录见 [CHANGELOG](CHANGELOG.md)。许可证为 MIT。
