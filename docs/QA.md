# QA 记录（2026-10-01）

验证版本：SubscriptionLibrary 0.1.1 / 0.1.2 / 0.1.3 / 0.1.4，MoviePilot 3.0.4。

## 真实订阅发现的问题

随后新增三部真实动漫订阅测试，发现 0.1.1 的下载上下文读取使用了 `mediainfo`，但 MP 真实 `Context` 的规范字段是 `media_info`。用规范字段复现：归档为空的正常候选也被错误拦截，原因是“归档保护状态不可用”。

原宿主 SDK QA 使用 `ContextSnapshot(mediainfo=...)`；该模型允许额外字段，因此这项检查虽通过，却没有代表真实生产输入。旧检查结论不能证明真实自动下载正常。

0.1.2 已修正规范字段读取，测试替身和 SDK QA 也改为规范字段，并增加真实运行时 `Context` 检查。当时 54 项本地回归测试通过；0.1.2 在线原生升级完成，宿主 SDK 6 项检查通过；三条真实订阅生成下载任务。

实际下载又暴露出动漫历史季号为空的情况。0.1.3 验证原生订阅来源的媒体身份、季号及剧集组，补充缺失季号；已有季号或无效来源仍保持原策略。60 项回归通过，已通过原生市场升级。

## 真实订阅验收

在现有生产 MP 新增三条独立动漫订阅，以新任务为测试范围，保留原有订阅：

- 三条订阅均实际搜索、生成 qBittorrent 下载任务，并有 MP 下载历史。
- 将一条订阅起始集数由 0 改为 3，qB 原生文件清单确认第 1、2 集 priority=0，第 3 集 priority=1；混合下载任务仍保留。这次前两集尚未落盘，不能据此声称已验证它们的文件删除。
- 取消两条测试订阅后，qB 原生查询确认两任务均不存在；MP 下载历史均不存在。
- 其中一个任务取消前已有实际 `.!qB` 源文件。自动巡检后原路径及挂载别名均不存在，待重试计划为空且没有运行错误。
- 原有两条身份关系不明确的整理记录继续保留；兼容修复没有把未知记录推定为第一季。

剩余测试订阅已下载完成，通过原生文件整理成功入库。发现整理历史季集字段为空但目标文件有明确 SxxEyy 标记，0.1.4 补充这个读取依据。实际范围清理继续验收。

隔离流程覆盖：

1. 有订阅时保留下载源、媒体库硬链接和字幕。
2. 修改起始集数，删除旧集及字幕，保留新集和混合下载任务。
3. 模拟容量清理连同历史记录消失，重载后仍阻止旧集补下载、允许新集。
4. 显式恢复下载后不会因旧的缺失记录再次归档。
5. 历史删除失败时保存待重试计划；重载后完成重试并确认取消意图。
6. 保留没有登记的相邻文件，禁止越出隔离目录删除。
7. 四个独立进程同时提交取消意图，持久化队列没有丢失条目。
8. 测试目录完成后自动移除。

## 可复现命令

在源码仓库中运行：

```sh
python -m unittest discover -s tests -v
python tools/qa_sandbox.py
```

在已有 MoviePilot 宿主容器内运行同一个 QA 工具时：

```sh
python qa_sandbox.py \
  --plugin-dir /app/app/plugins/subscriptionlibrary \
  --workspace-parent /media/downloads \
  --native-sdk
```

`--workspace-parent` 必须指向可写的既有目录。工具仅管理其新建的临时子目录；不读取现有媒体库存或更改在线插件数据。`--native-sdk` 仅在独立测试进程中调用事件处理函数，使用生成的媒体身份和归档状态，不发布事件到在线 MP。

## 尚未验证的生产链路

- 隔离测试中的下载器和历史操作使用测试替身；它们不能证明真实 qBittorrent 删除、MP 历史删除和媒体服务器刷新已经串联成功。
- 已验证真实下载器取消、部分源文件及下载历史清理；整理后的媒体库文件、整理历史及媒体服务器可见性链路仍待实测。
- 测试了持久化状态和进程重载、原生插件重载；没有重启整个生产容器。
- 在线两条身份/季号/本地存储关系不明确的整理记录保持保留，不能按标题猜测删除。

因此当前结论是：列出的规则、隔离文件清理、持久化、SDK 契约，以及实际下载任务与部分源文件取消 QA 通过；整理后的媒体库文件链路仍在验收。
